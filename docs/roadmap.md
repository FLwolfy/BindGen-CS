# 4.0 convergence and delivery order

The architecture separates neutral algorithms, explicit standard implementations and optional official extensions. Installing BGCS provides ordinary generation; consumers always own compilation, linking, packaging, deployment and execution.

1. Complete Core/Engine, unified C/C++ bridges and explicit composition.
2. Review actual dependency, input, cache, lifetime and publication paths.
3. Compile the whole source, then run concentrated functional, consumer and performance checks.
4. Build isolated same-source candidate packages and consume their actual bytes.
5. After committing, run the four exact-commit remote gates, then verify immutable publication and public package consumption.

One targeted Browser Mono Wasm/AOT aggregate regression belongs to the Linux repository job. It is not a product build feature. Other unexecuted combinations remain explicit.

Current status comes from records/acceptance and execution receipts. Source, compilation, tests, package consumption and publication are different evidence. Maintenance is extension-first; future core changes require a specific defect or representation gap.
