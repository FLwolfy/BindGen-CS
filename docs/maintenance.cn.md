# 维护约定

目标是核心稳定、有回归保障，不承诺只有升级 .NET 才需要修改。

1. 优先使用已有接口：目标输入、ABI 分类、runtime 能力、lowering、语义配置与托管投影。
2. 无法表达时，记录具体缺口和最小契约增量。
3. 已复现的生成或 Runtime 缺陷在所属模块修复，不把某个库的补丁散布到各个 emitter。
4. 优化不能关闭源码身份、清理、ABI 或完整输入检查。
5. parser、SDK、runtime 或 ABI 规则变化后，重跑受影响组合。

新 SDK 路径、宏、现有模型能表达的 ABI 规则、库协议与符号取得方式，通常只需接口实现。新的语言结构、物理调用机制或未建模的生命周期协议，仍可能要求核心修改。

支持状态分别记录解析、生成、仓库消费者编译和真实调用。资源存在或能力声明不等于运行认证。支持声明依据[发布历史](releases/README.md)所链接的同提交回执；源码不变量维护在[架构审查](architecture-review.md)。历史开发记录不能作为当前支持声明。
