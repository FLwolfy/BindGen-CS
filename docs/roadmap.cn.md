# 4.0 收敛与交付顺序

当前架构由中立核心、明确的基础实现和按需官方扩展组成。普通用户安装 BGCS 即可生成；消费项目始终自行编译、链接、包装、部署和运行。

1. 完成 Core/Engine、统一 C/C++ 桥接和显式扩展组合。
2. 沿真实调用链审查架构、输入、缓存、生命周期和发布。
3. 整体编译后集中执行功能、消费和性能测试。
4. 制作同源码隔离候选包并验证实际消费。
5. 提交后执行四项同提交远端门禁，再进入不可变版本发布与公共包验证。

本次固定 Browser Mono Wasm/AOT aggregate 回归在 Linux 作业运行一次。它属于仓库消费者，不是产品构建功能；其他未执行平台保持明确状态。

已验收版本和同提交执行回执见[发布历史](releases/README.md)，[开发台账](history/4.0-development-ledger.md)仅作历史参考。源代码、局部编译、测试、包消费和发布是不同证据，不能互相替代。架构进入维护后，新增需求优先通过接口；核心变更必须由具体缺陷或表达缺口驱动。
