# BGCS 诊断参考

<!-- Generated from eng/diagnostics/catalog.json; edit that source and regenerate. -->

`bindgen-cs explain CODE` 显示同一目录中的英文原因与处理方法。具体诊断消息、源码位置和阶段提供本次失败的上下文。

## BGCS-ANALYSIS-INPUTS — 分析输入释放失败

原因：捕获或释放冻结的分析输入时失败。

处理：根据详细的文件或插件错误关闭冲突句柄，修正输入声明后创建新请求。

## BGCS-ANALYSIS-SESSION — 原生分析会话失败

原因：目标、frontend、原生事实图或分析扩展未能返回有效模型。

处理：根据阶段、目标与源码诊断修正解析参数、目标前提或失败扩展，再运行 inspect。

## BGCS-C-ABI — C 声明缺少可支持的直接 ABI

原因：C 声明缺少精确固定原型或包含不支持的直接 ABI 类型；C++ 事实图不能直接进入 C 分析。

处理：补全 C 原型与受支持载体；C++ 使用桥接路径，不支持的签名使用显式原生 shim。

## BGCS-C-INTERNAL-LINKAGE — 配置的原生模块缺少 C 头文件辅助导出

原因：选中的 C 函数具有内部链接、头文件定义，或编译器确认的仅可直接调用 intrinsic 语义，没有独立可取地址的外部符号；预编译模块不会自动包含生成的辅助导出。

处理：把生成的 C helper 源码编译进配置指定的原生模块，使明确的包装导出实际存在，或提供声明的原生 shim。Windows 上单独的 helper 依赖 DLL 不会提供父模块导出。

## BGCS-CACHE-BUDGET — 生成缓存条目超过预算

原因：生成阶段成功，但序列化结果超过配置的单条目缓存上限。

处理：检查产物大小，在受支持范围内提高 cache.maximumEntryBytes，或保留此次成功但不缓存的结果。

## BGCS-CACHE-MISS — 缓存阶段未被复用

原因：缓存条目缺失、损坏、过期，或未通过当前完整契约复核。

处理：查看具体原因；正常重新生成可以重建过期或损坏条目，不要关闭 ABI 检查来接纳旧字节。

## BGCS-CACHE-STORE — 已发布结果无法写入缓存

原因：生成已经成功发布，但写入可复用的不可变缓存条目失败。

处理：检查缓存目录权限、空间与冲突句柄；正式生成结果仍然有效。

## BGCS-CACHE-UNAVAILABLE — 生成缓存不可用

原因：准备、标识或读取符合条件的生成缓存时失败。

处理：检查缓存错误，选择可写且不与输入或输出重叠的目录，或关闭缓存并保留普通生成与验证。

## BGCS-CALL-ABI — 物理调用 ABI 不受支持

原因：所选 ABI 实现无法确认最终物理签名的正向或反向调用安全；实现提供被拒绝的原生类型身份时，诊断保留其准确源码位置。

处理：使用受支持的指针桥接或显式原生 shim，或提供具有准确调用计划的适用 ABI 实现。不能用大小相同代替调用兼容性。

## BGCS-CONSTANT-OMITTED — 对象宏缺少受支持的标量值

原因：编译器未能证明该对象宏具有受支持的标量值；原始替换文本仍保留在原生事实中。

处理：通过原生或 interop 变换实现所需的非标量语义，或不投影该宏；不会把文本、类型别名或上下文宏猜成数值常量。

## BGCS-CSHARP-ABI-PLAN — C# ABI 规划不能表达该原生声明

原因：在已解析的 ABI、托管运行环境和导入模式下，该原生声明缺少已证明正确的 C# 存储或按值调用表示；附带源码位置指向相关声明或字段。

处理：根据详细类型、布局或调用约束，使用显式指针形式的原生桥接或 shim，或者选择已独立验证兼容的运行环境与导入模式；不能只根据大小相同替换原生类型。

## BGCS-DIFF-METADATA — 生成元数据存在逻辑字段变化

原因：Diff 发现缓存运行信息之外的元数据变化，并报告有限数量的 JSON 路径及变化前后的值。

处理：核对这些字段是否符合预期的输入或配置修改。请求未变时逻辑验证证据应保持一致；不能因为生成源码未变就忽略 ABI 或输入记录的变化。

## BGCS-DIFF-OUTPUT — 无法安全比较已有输出

原因：Diff 在比较候选生成前无法读取或验证上一套受管理输出。

处理：检查原有所有权清单、产物 hash、路径与访问权限，恢复完整输出后重试 diff。

## BGCS-DOCTOR-CONFIGURATION — 配置前提无效

原因：Doctor 无法加载或验证分组配置及其声明的插件。

处理：先修正 schema、路径、配置组合或插件错误，再检查编译器与 worker 前提。

## BGCS-DOCTOR-TARGET — 原生目标无法解析

原因：无法根据显式配置与已安装环境解析请求的目标、SDK、sysroot 或工具链。

处理：修正目标身份及 SDK、工具链路径，或注册所需目标 provider 后重试 doctor。

## BGCS-DOCTOR-WORKER — 解析 worker 资源无效

原因：匹配宿主的 worker 执行闭包缺失、不完整或未通过声明的 hash 验证。

处理：重新部署匹配生成器宿主的完整 worker 资源，不要按生成目标选择解析器资源。

## BGCS-FRIENDLY-OMITTED — 易用 API 缺少完整契约

原因：请求的字符串或缓冲区包装无法证明编码、范围、方向、保留、生命周期或对齐契约。

处理：在有依据时补全 semantics.stringParameters 或 semantics.bufferParameters 的精确声明；否则使用正确的 raw ABI。

## BGCS-FRONTEND-CLANG — Clang 报告源码诊断

原因：解析 worker 转发了当前语言、目标与有效参数下的 Clang 诊断。

处理：根据原始源码位置和编译器消息修正声明、宏、include 路径或目标 SDK 输入。

## BGCS-GENERATION-SESSION — 生成会话无法完成

原因：必需的生成、lowering、ABI 规划、插件、验证或发布阶段失败。

处理：根据详细错误及源码、目标上下文修复；无法表达 ABI 时增加受支持的中立 lowering 或原生 shim。失败不会替换上一套完整输出。

## BGCS-MACRO-ALIAS — 函数宏别名没有唯一可验证的导出

原因：编译器确认的对象式宏引用了原生自由函数，但最终互操作模型中该确切函数没有合格的主导出，或对应多个主导出；输入适配器不算主导出。

处理：通过声明选择与 lowering 保留确切原始函数，或提供明确且无歧义的托管 projection。BGCS 不会为宏别名虚构导出，也不会猜测重载。

## BGCS-NATIVE-GRAPH — 原生事实图不一致

原因：分离后的原生声明或类型包含缺失、重复、循环或不相容的事实。

处理：修正产生该事实的 frontend 或原生变换，不要用默认类型或布局值掩盖错误后继续生成。

## BGCS-PUBLICATION-CLEANUP — 已提交发布的备份清理失败

原因：完整候选已发布，但旧受管理备份或 journal 清理失败。

处理：检查对应受管理路径、句柄与空间，保留当前有效清单，并按发布恢复协议处理残留。

## BGCS-SAFETY-ALLOCATOR — 拥有型输出缺少匹配分配器

原因：拥有型原生值缺少完整的分配与释放域契约。

处理：通过 semantics.ownedResults 或中立 interop 契约声明有依据的释放函数与域；无法确定时保留 raw pointer。

## BGCS-SAFETY-ASYNC — 原生异步完成生命周期不完整

原因：异步原生访问没有为保留的回调或缓冲区确立最终完成边界。

处理：在中立 async 契约中声明真实最终完成协议；原生访问真正结束前保留 pin、callback 和模块 lease。

## BGCS-SAFETY-CALLBACK — 回调生命周期不完整

原因：回调契约未明确原生保留、unregister 完成和正在执行的调用生命周期。

处理：按库协议提供显式中立回调契约，或在原生访问真正结束前自行管理 raw callback 生命周期。

## BGCS-SAFETY-CALLBACK-THREAD — 回调线程契约不完整

原因：原生回调允许的线程或受线程约束的释放域未知。

处理：在中立语义契约中声明允许的回调、释放线程，并同步这些线程访问的应用状态。

## BGCS-SAFETY-EXTERNAL-TYPE — 外部载体需要独立 ABI 证据

原因：用户提供的托管类型跨越原生边界，但缺少完整匹配的存储与调用 ABI 证据。

处理：提供独立验证的目标布局与调用相容性，或使用原生指针、桥接表示；类型名或大小相同不足以证明安全。

## BGCS-SAFETY-LENGTH — 原生缓冲区边界不完整

原因：所选缓冲区缺少可证明的长度、容量或已写数量关系。

处理：在受支持时使用 semantics.bufferParameters 声明精确关系，更复杂协议使用显式 interop 契约或原生 adapter。

## BGCS-SAFETY-LOWERING-BYPASS — 显式选择了不安全 lowering

原因：lowering 依据显式不安全策略被接纳，而非完整 ABI 与生命周期证明。

处理：保留独立原生调用和生命周期测试，并在可用时使用声明且已验证的中立 lowering 替代绕过。

## BGCS-SAFETY-OWNERSHIP — 原生指针所有权不完整

原因：返回的数据地址缺少具有明确证据来源的所有权或有效期事实；原始 ABI 本身不能证明生命周期。

处理：通过 semantics.ownedResults 声明匹配释放、semantics.borrowedResults 声明模块有效期，或提供中立插件契约。可在 execution.diagnostics.errorCodes 中选择该警告以阻断发布；不按名称推断所有权或编码。

## BGCS-SESSION-RELEASE — 生成服务释放失败

原因：会话拥有的服务或插件在释放时失败。

处理：修复指定扩展的清理并释放其资源，重新执行请求，使生命周期失败进入完整结果。

## BGCS-SOURCE-CLEANUP — 生成发布完成后私有源码存储清理失败

原因：完整候选产物已经提交，但宿主拥有的私有贡献源码存储未能清理。

处理：检查明确的私有存储路径与维护错误，解除冲突句柄或文件属性，再重试已验证归属的清理。已发布产物保持有效；提交前贡献服务释放错误仍会阻断发布。

## BGCS-WORKSPACE-DEPENDENCY — 工作区前置项目失败

原因：某工作区项目因显式前置项目失败而被跳过。

处理：修复并重跑指定前置项目；依赖项目不会发布基于失败上游工作的结果。

## BGCS-WORKSPACE-PROJECT — 工作区项目失败

原因：工作区执行依赖图时有一个项目请求失败。

处理：查看该项目配置及其生成、构建诊断；独立项目可以完成，但整个工作区仍然失败。

## BGCSCPP-INSTANTIATION — C++ 模板需要具体实例

原因：选中的主类模板或函数模板没有显式具体特化。

处理：在 bridge.cpp.templateInstantiations 中声明所需类或函数实例，并提供完整类型、值参数。

## BGCSCPP001 — C++ 声明缺少安全 lowering

原因：没有已注册 C++ lowering 能保留选中声明及其 ABI、生命周期契约。

处理：增加类型化 Contracts-only lowering、配置 recipe、具体模板实例或显式原生 shim。

## BGCSCS001 — 托管 backend 无法保留语义

原因：托管模型请求的类型或调用无法由所选 C# backend 在保留契约的前提下表达。

处理：使用受支持的中立 projection、lowering 或原生 shim，或先实现并验证缺少的 backend 能力。

## BGCSIO001 — 产物发布失败

原因：暂存或提交生成产物时文件系统操作失败。

处理：检查确切路径、权限、空间与打开的句柄，保留上一套完整输出，并按发布恢复协议处理提交中断。
