# BGCS 4.0.0

BGCS remains a source generator and independent binding Runtime. It produces C#,
necessary C/C++ bridge source, manifests and diagnostics. Consumer projects own
compilation, linking, packaging, deployment and execution.

## Architecture and interfaces

- `BGCS.Core` owns neutral models and directly implementable extension interfaces.
  `BGCS.Engine` coordinates generation without concrete host, target or frontend
  references. The `BGCS` product supplies the standard composition.
- Target, managed-runtime and call-ABI providers are independent. Exact call plans
  bind signature, direction, target, runtime profile and implementation identity.
- Factory registration, explicit replacement, stable ordering and session disposal
  use one registry. Custom code can live in the generation tool itself; publishing
  a plugin or using a manifest is optional.
- Optional BrowserWasm, NativeAot, Android, AppleMobile and FreeBsd implementations
  are separately packaged and explicitly activated. The full BGCS product does not
  require these packages. Parsing support is distinct from runtime certification.

## Native and managed generation

- C and C++ use the typed NativeBridge flow. Default aggregate boundaries use typed
  pointer and output channels; explicit direct calls require an applicable ABI plan.
- Original native facts remain distinct from generated proxy types and exports.
  Finite variadic adapters and virtual proxies retain source identity and semantics
  without reparsing the original source as an expanded synthetic declaration graph.
- Custom type/callable lowering, aggregate callbacks, ownership, error boundaries
  and source requirements remain explicit. Retained callbacks need native quiescence
  and complete frame exit; cancellation alone cannot release native-accessed memory.
- FunctionTable, DllImport, LibraryImport, instance/static APIs, split/single-file
  output and Runtime package/source delivery remain available.
- Portable native source requirements use logical input roots and a typed
  `metadata/native-source.manifest.json`; physical root bindings stay session-local.
  No compiler commands or binary packaging plans are embedded.
- Capability reports describe actual raw, friendly, bridge-only, excluded or
  unsupported output. They do not claim that a consumer was compiled or executed.

## Breaking changes

4.0 uses schema version 2 and the `bridge` / `bridge.cpp` configuration groups.
Runtime selection uses open implementation IDs. Generation extensions reference
`BGCS.Core`; `BGCS.Contracts`, Cpp2C ports, old configuration forms and forwarding
APIs are not provided. The ordinary entry is `BindingGenerator.CreateDefault()`;
an independent Engine composition must register its required implementations.

There is no NativeBuild product, MSBuild integration, consumer-build command,
compatibility package or automatic consumer-project update.

## Parser, requirements and provenance

.NET 10 / C# 14, C17 and C++23 remain the baseline. The SDK/runtime lock is updated
to SDK 10.0.402 with preview SDKs disabled. The locked LLVM/ClangSharp family is
unchanged. Parsing continues in an isolated, versioned worker with authenticated
resources and bounded diagnostics.

Release evidence must identify the exact accepted source commit, workflow runs,
physical package hashes and isolated consumption results. Historical 3.x reports,
dirty local runs and package existence alone do not certify this version. See
[acceptance](../acceptance.md), [capabilities](../capabilities.md) and
[publishing](../publish.md) for the precise gates and support boundaries.
