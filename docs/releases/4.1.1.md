# BGCS 4.1.1

## Anonymous native storage

This patch fixes native assertions that could emit a compiler diagnostic name as
a C type declaration. Unnamed records, named members and injected anonymous
members retain distinct source facts. Injected member offsets come from the
compiler's field declarations, including alignment padding; they are not inferred
from the preceding field.

Unnamed declarations retain their logical owning scope for managed projection.
That scope is not accepted as a native type name; existing managed carrier names
remain stable rather than being renamed as a side effect of the fact correction.

Source declarations and native assertions share the existing type formatter.
Unnamed storage is verified through a named owner and recursive member paths,
including sizes, standard-layout offsets, arrays, leaf types and qualifiers.
Unexpressible required proofs fail generation. C17 output does not depend on
C23 `typeof`, and no platform-specific type list or generated-text patch is used.
The MSVC C branch documents its VS17.9+ `__typeof__` extension requirement for
relative offsets inside anonymous arrays; other C17 compilers do not need it.

The native model revision is 4. Old frontend cache models are misses and worker
model mismatches are rejected. The framing protocol, extension ports, configuration
schema and 4.x source-generation architecture are unchanged.

## Verification and boundaries

Repository regressions cover user and system headers, C/C++, typedefs, nested
anonymous records, alignment-sensitive injected members and equal-size negative
type/layout changes. The existing desktop and browser fixtures exercise aggregate
arguments, results and reverse callbacks with anonymous storage. The browser
fixture also compiles real target system-header storage requirements without
copying or invoking synchronization objects.

The release requires all four existing same-revision gates and installed/public
package consumption. Release notes describe the implementation; passing receipts
are published separately.

BGCS continues to emit source, manifests and diagnostics. Consumer projects own
compilation, linking, deployment and execution. LLVM/ClangSharp and .NET baselines
are unchanged. The immutable 4.1.0 release is preserved.
