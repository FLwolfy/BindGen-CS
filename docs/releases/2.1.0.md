# BGCS 2.1.0

## Architecture and extensibility

- Separate parser integration, neutral binding and bridge models, C# emission,
  runtime support, and the command-line application into eight production projects.
- Resolve native targets through explicit providers with separate SDK, sysroot,
  ABI, and generator-host descriptions.
- Generate C++ bridges through analysis and lowering before emitting the frozen
  bridge model. Keep BGCS independent of downstream game engines and applications.

## Parser portability

- Embed matching Clang 20 builtin headers in `BGCS.CppAst/Resources/Clang`,
  together with their provenance and third-party license.
- Preserve compiler header-search order, SDK wrapper headers, framework paths,
  and C++ standard-library selection across supported desktop hosts.
- Follow SDK header aliases without directory cycles, and isolate discovery caches
  by compiler, language, and target settings.
- Supply accepted macOS Intel parser runtime assets in the parser package.

## Verification and packaging

- Execute native calls through DllImport, LibraryImport, and FunctionTable consumers
  in desktop NativeAOT, WebAssembly interpreter, and WebAssembly AOT deployments.
- Run the complete CI matrix on Windows x64, Linux x64, and macOS Intel before
  release packaging. Retain negative invocation checks and independent evidence.
- Publish seven library packages and a tool pointer package with five RID packages,
  including symbols, SPDX SBOM, and signed provenance.
- Organize solution projects and project files by responsibility; maintain ordinary
  contribution guidance without repository AI instruction files.

## Requirements and scope

Generated assemblies and the tool target .NET 9. The RID-specific tool packaging
format requires the .NET 10 SDK for installation. Consult the
[publishing guide](../publish.md), [target and host boundaries](../ci-portability.cn.md),
and [capabilities](../capabilities.md) for prerequisites and tested scope.

This release includes API and configuration changes from 2.0.x. Regenerate bindings
and update consumers against the current documentation and API snapshots.
