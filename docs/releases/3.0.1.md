# BGCS 3.0.1

This patch corrects native source portability and dependent-template parsing. BGCS
continues to generate source only; consumers own compilation, linking and deployment.

- Generated native includes use verified relative spellings from the declared
  `source.includeDirectories` roots. A project root is added before parsing only
  when entry headers need it. Ambiguous or unmapped inputs fail before publication.
- `GenerationResult.nativeSources` exposes typed `NativeSourceManifest` records;
  `nativeInputRoots` supplies separate session-local root bindings. Reopen verified
  manifests with `BindingArtifactManifest.ReadNativeSources` and map their roots to
  the consumer's frozen input tree. The existing `bridge.manifest.json` filename
  now carries the typed requirements; it contains no executable build plan.
- Static export adapters reference generated bridge headers relative to their own
  artifact location, including after original inputs and outputs move separately.
- C++ bridge headers have a header media type, so manifest consumers do not compile
  them as translation units. Generated sources, headers, shim sources and parsed
  dependencies retain their distinct roles and content identities.
- Repeated dependent uses such as `std::pair<iterator, bool>` retain borrowed type
  references rather than reparenting shared types. Declaration ownership checks
  remain strict.
- Reference fields retain compiler-established slot storage separately from the
  referent type size. Graph extent validation and generated consumer assertions
  check those distinct facts instead of treating a large referent as inline storage.
- Worker failures preserve bounded exception details in `BindingDiagnostic.details`
  while ordinary summaries remain concise. Parser builtin input identities are
  separate from consumer SDK and plugin inputs.
- Directory membership uses the enumerated entry kind and exact link target,
  preserving its digest and revalidation rules while avoiding unrelated Unix
  user/group permission queries during cache checks.

Contracts API minor 1 adds these neutral records and optional diagnostic/frontend
facts without replacing existing extension ports. The previous `v3.0.0` tag and
packages remain immutable. Actual release and platform evidence belongs to the
same-revision CI and installed-product receipts, not this change description.
